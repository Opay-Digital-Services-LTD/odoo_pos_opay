OPay POS Terminal

Send Odoo Point of Sale payment amounts to a configured physical OPay terminal and complete the exact payment line only after an authenticated final result.

Platform: Odoo 19 with Point of Sale. Listing: Free under the LGPL-3 license.

Installation and configuration

  1. Install this package on Odoo 19 with Point of Sale.
  2. Create a POS payment method using a Bank journal and Terminal integration.
  3. Select OPay and enter the OPay-supplied merchant, terminal, and authentication values.
  4. Add the payment method to the intended POS configuration.
  5. Register the generated public HTTPS webhook URL with OPay.

Selecting OPay deliberately enables the external OPay data transfer described below. The payment method maps to one unique physical terminal.

Configure the OPay merchant, terminal, and server-side authentication values.

Native POS terminal flow

OPay is registered through Odoo's payment-terminal interface. The cashier selects OPay on the standard Payment screen, and the Odoo server sends the amount to the terminal configured on that payment method.

Authenticated final status

Create Payment acceptance leaves the line waiting. A payment is completed only after a correlated SUCCESS result from the authenticated webhook or the cashier's Check Payment Status action.

Included features

  • OPay terminal configuration on Odoo POS payment methods.
  • Physical-terminal Create Payment for NGN transactions.
  • Stable payment references and duplicate Create protection.
  • Authenticated webhook processing with exact attempt correlation.
  • Cashier-triggered Check Payment Status using Query Order.
  • SUCCESS, FAIL, CLOSE, CANCEL, PENDING, and uncertain-state handling.
  • Read-only operational payment-attempt records.
  • Multi-company isolation and safe operational logging.

Cashiers can check the existing payment without creating another OPay order.

Payment lifecycle

  1. The cashier selects the configured OPay payment method.
  2. Odoo sends the amount to the assigned physical terminal.
  3. The payment line remains waiting while the customer pays.
  4. The authenticated webhook or Check Payment Status resolves the existing attempt.
  5. Only a correlated SUCCESS result completes the payment line.

Status resolution

Query Order is not polled automatically. Final status comes from the authenticated OPay webhook or an explicit cashier Check Payment Status action. PENDING and uncertain outcomes remain waiting and never trigger a blind Create Payment retry.

Authorized backend users can inspect safe operational payment details.

Security boundary

Merchant identifiers, terminal configuration, clientAuthKey, and RSA keys remain on the Odoo server. The POS browser does not call OPay directly and does not receive the authentication key or key material. API responses and webhook notifications are authenticated before transaction data is trusted.

External service and data transfer

This addon requires the external OPay cloud POS service. When the cashier deliberately starts or checks an OPay payment, the Odoo server sends OPay the configured Business ID, Branch ID, terminal serial number, payment reference, amount, NGN currency, expiry, scene/sub-scene, split indicator, and authenticated protocol envelope. The addon does not send customer, card, PIN, or account details in its Create Payment or Query Order payloads. Odoo receives OPay order references, transaction statuses, response messages, timestamps, and authenticated webhook/query transaction data.
